# 🚩 Mybatis 및 DAO 작업 가이드라인

> **실행 조건:** 채팅 문구에 **"ㄱㄱ"**이라는 단어가 포함될 경우 아래 규칙을 적용한다.
> **주의 사항:** 결과는 **채팅창에만 표시**하며, **실제 소스 파일에 직접 반영**하지 않는다.
> **필수** 프롬프트 규칙을 준수

---

## 1. 작업 범위 준수 (가장 중요)

- **단일 라인 또는 특정 라인 범위만 지정된 경우 (`@[파일경로:L시작-종료]` 형식):**
  - ⚠️ **절대 주의:** 지정된 라인 범위 밖의 코드는 변환하지 않습니다. 해당 라인 내에 있는 쿼리 및 소스코드만 MyBatis XML과 uxbDAO 코드로 변환하여 제시합니다.
  - 메소드 전체나 주변 쿼리를 임의로 포함하여 작업해서는 안 됩니다.
- **클래스 또는 파일 전체를 요청한 경우 (라인 범위가 없거나 파일 전체인 경우):**
  - 각 함수별로 MyBatis 및 uxbDAO 작업을 진행하고 작업 내용을 정리합니다.

---

## 2. 상단 타이틀 작업

작업 대상의 위치를 명확히 표시합니다.

- **형식:** **🚩작업영역: [패키지.클래스] - [함수명] [라인번호 링크]**
- **링크 작성 규칙:**
  - `file:///` 프로토콜로 시작하는 절대 경로 사용.
  - 윈도우 경로의 백슬래시(`\`)는 모두 슬래시(`/`)로 변환.
  - 형식: `[L시작-종료](file:///경로#L시작-L종료)`
- **예시:** **🚩작업영역: com.pan.som.dao.bunker.OBNBnkDAO - selectList - [L120-132](file:///D:/panocean-v2/src/main/java/com/pan/som/dao/bunker/OBNBnkDAO.java#L120-L132)**

## 3. MyBatis XML 작업

SQL 매핑 파일 작성 시 적용할 규칙입니다.

- 필수 체크 사항
  - 현재 작업중 채팅창 및 세션에서 동일 쿼리(조건도 동일)가 있는지 확인하고 존재하면 재활용하게 처리해줘 (재활용건은 쿼리 생략)

### ① Namespace 및 ID

- **Namespace:** 클래스명에서 "DAO", "Service", "VO" 접미사를 제외한 명칭.
- **ID:** Java 소스의 함수명 또는 공통 처리 규칙에 따라 테이블 이름을 조합하여 설정.

### ② 데이터 처리 및 쿼리 포맷

- 쿼리 상단 주석 포맷
  - 예: <![CDATA[ /* ICCCgoClmM.iccCgoClmMSelectInvoiceSts */ ]]>
    => <![CDATA[ 
           /* ICCCgoClmM.iccCgoClmMSelectInvoiceSts */ 
          ]]>
- **Null/공백 처리:** Java의 `Formatter.nullTrim` 로직이 있다면 쿼리 내에서 `TRIM(#{변수명})`으로 구현.
- **쿼리 형식:** Oracle 문법을 준수하며, 기존의 검색 조건을 모두 포함하여 작성.
- **클래스 기반 컬럼 매핑:** 임의로 테이블 스키마의 모든 컬럼을 추정하여 `INSERT`/`UPDATE` 문 등에 일괄 포함하지 마십시오. 반드시 실제 Java 클래스(VO, DTO 등)에 명시적으로 정의된 필드들만 확인하여 매핑 대상으로 작성해야 합니다.
- 긴 작업은 생략하지 말고 모든 작업을 진행
- **CDATA 주석 블록 분리**:
  - 쿼리 태그( `<select>`, `<insert>` 등)의 최상단에 네임스페이스와 아이디를 포함한 주석(`/* Namespace.ID */`)만 별도의 `<![CDATA[ ... ]]>` 블록으로 작성합니다.
  - 실제 SQL 문은 `]]>` 뒤에 이어서 작성합니다.
- commonDao.defaultSearch 문일 경우 첫번째 파라미터 참조해서 select 문 컬럼 표시
  - 예 : commonDao.defaultSelect(new ICCNyClmFundInfoVO(),...) 에서 ICCNyClmFundInfoVO 클래스의 defaultQry 문자열을 참조
- 비교 연산자: <>(Not Equal) 연산자 대신 XML에서 안전한 !=를 사용하거나, &lt;&gt;로 작성한다.
- 문자열 내 특수 문자: SQL 내 문자열에 포함된 <와 >는 반드시 Entity Reference (&lt;, &gt;)로 변환한다. (예: '<br>' → '&lt;br&gt;')
- **test 속성 내 문자열 비교:** XML의 `test` 속성 내에서 문자열 값을 비교할 때는 바깥쪽을 홑따옴표 `'`, 안쪽 문자열을 쌍따옴표 `"`로 감싸서 작성한다. (예: `test='result2 == "Y" and result3 != "SOD"'`)
- SQL 문자열 내에 포함된 특수 문자 처리
  - < → &lt;
  - > → &gt;
  - & → &amp;
  - > = → <![CDATA[>=]]>
  - <= → &lt;=
  - <> → <![CDATA[<>]]>
- **단건(상위 1건) 제한 조회:** `commonDao.getString` 등을 전환하여 상위 1건만 조회해야 하는 경우, MyBatis 쿼리 내에서 `ROWNUM = 1`을 지정하여 쿼리를 작성한다. 필요에 따라 인라인 뷰(`SELECT ... FROM (SELECT ...) WHERE ROWNUM = 1`)를 사용하여 정확한 단건 결과를 보장한다.
  - 쿼리 작성 후 오라클 기준 정렬
    - 컬럼 줄바꿈 처리
      - format 형식 예

```xml
<select id="cbdVslSpdBnkMSelectVslCode" parameterType="map" resultType="string" useCache="false" timeout="0">
	<![CDATA[
		/* CBDVslSpdBnkM.cbdVslSpdBnkMSelectVslCode */
	]]>
	SELECT
		VSL_CODE
	FROM
		CBD_VSL_SPD_BNK_M
	WHERE
		VSL_CODE = #{vlsCode}
		AND YEAR_MONTH LIKE #{year} || '%'
		AND ROWNUM = 1
	GROUP BY
		VSL_CODE
</select>
```

### ③ 속성 설정 (한 줄로 표시)

- **공통:** `timeout="0"`, `parameterType`은 기본적으로 `"map"`을 사용한다.
  - `commonDao.defaultInsert`, `commonDao.defaultUpdate`, `commonDao.defaultDelete` 등을 변환할 때 전달하는 파라미터가 클래스(VO, DTO 등) 타입인 경우, `parameterType`에 패키지명을 포함한 클래스 타입(예: `com.pan.som.common.dto.basicData.CBDCanalPanamaCgoMDTO`)을 지정한다.
- **select:** `parameterType="map" resultType="[규칙에 따른 타입]" useCache="false" timeout="0"`
  - `commonDao.getObject` 일 때: `resultType`을 무조건 `"map"`으로 고정한다.
  - `commonDao.defaultSelect` 일 때: `resultType`을 무조건 `"map"`으로 고정한다.
  - 받는 Java 변수/파라미터가 String 일 때: `resultType="string"`으로 설정.
- **insert/update/delete:** `parameterType="[클래스타입 또는 map]" timeout="0"`

### ④ 코드 표시 형식

- MyBatis XML 쿼리를 표시할 때는 여러 개의 쿼리가 있더라도 하나의 XML 코드 블록 안에 모아서 한 곳에 표시한다.

## 4. uxbDAO 작업 (Java)

DAO 클래스 내의 로직 전환 규칙입니다.

- **기본 원칙:** 기존 함수의 파라미터 및 리턴 타입을 유지한다.
- **파라미터 세팅:**
  - 파라미터가 클래스(VO , DTO 등) 인 경우 : 클래스를 파라미터로 전달
  - 파라미터가 클래스(VO , DTO 등)가 아닌 경우: 함수 내에서 `HashMap`을 생성하여 값을 담아 전달.
  - 파라미터가 없는 경우: `HashMap` 생성 없이 `null` 전달 또는 호출 시 생략.
- **메서드 변환:**
  - **일반 조회:** `commonDao.getObjects` → `uxbDAO.select`
    - DAO Java 코드에서는 uxbDAO.select 결과를 commonDao.getObjects 로 감싸서 강제 매핑(Casting) 하도록 작성한다.
      - 예시: `return commonDao.getObjects(SCBWrkTnkFrtInfoDTO.class, uxbDAO.select("namespace.id", 파라미터));`
  - **단건 조회 (getObject):** `commonDao.getObject`
    \_ 예시 : `(SCBWrkTnkFrtInfoDTO)commonDao.getObject(SCBWrkTnkFrtInfoDTO.class, (Map)uxbDAO.selectObj("namespace.id", 파라미터));`
  - **defaultSelect 결과 처리:**
    - `commonDao.defaultSelect`
      - 예시: `(SCBWrkTnkFrtInfoDTO)commonDao.getObject(SCBWrkTnkFrtInfoDTO.class, (Map)uxbDAO.selectObj("namespace.id", 파라미터));`
  - ** commonDao.defaultDelete 결과 처리:** -> 'uxbDAO.delete'
    - 예시:
      ```java
      Map<String, Object> paramMap = new HashMap<>();
      paramMap.put("ocean_no", Formatter.nullLong(headDTO.getDlvry_fee_invo_no()));
      uxbDAO.delete("PostDeliveryFee.postDeliveryFeeInvoiceHDelete", paramMap);
      ```

  - **문자열 단건 조회 (getString -> selectObj):**
    - `commonDao.getString` 호출부를 `uxbDAO.selectObj`로 변환할 때, Java 소스 측에서는 리턴값이 `null`이 될 수 있으므로 반드시 `Formatter.nullTrim`이나 적절한 `null` 체크 처리를 추가하여 사용한다.
      - 예시: `String vsl_code = Formatter.nullTrim((String) uxbDAO.selectObj("namespace.id", paramMap));`
  - **예외 처리 (DTO 변환 시):**
    - DB 컬럼명(스네이크 케이스)과 DTO 필드명 매핑 문제로 resultMap 작성이 너무 번거로울 경우, XML은 `resultType="map"`으로 유지한다.
  - **자바 코드 표시 형식:**
    - 자바 코드를 표시할 때는 반드시 **[변경 전]**과 **[변경 후]**로 구분하여 각각 독립된 코드 블록으로 작성한다.
    - 예시:
      ##### [변경 전]
      ```java
      // 기존 코드
      ```
      ##### [변경 후]
      ```java
      // 변경된 코드
      ```
