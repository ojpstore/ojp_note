## 1.헤르메스용 64K 컨텍스트 모델 만들기 (Mac · WSL 동일)

여기가 이 가이드에서 가장 중요한 대목이라 **왜** 인지 꼼꼼히 짚을게요.

헤르메스는 매 요청마다 **도구 설명(tool schema) + 시스템 프롬프트**라는 큰 고정 분량을 모델에게 먼저 보냅니다. 그래서 컨텍스트 창이 작으면 일을 못 해요. 헤르메스는 **최소 64,000 토큰** 컨텍스트를 요구하고, 모자라면 다음과 같이 **실행 자체를 거부**합니다.

```
Failed to initialize agent: Model ... has a context window of 40,960 tokens,
which is below the minimum 64,000 required by Hermes Agent.
```

### 입문자가 꼭 알아야 할 두 가지가 있습니다.

1. **헤르메스는 모델의 "타고난(native) 컨텍스트"를 봅니다.** Ollama에 "이 모델 컨텍스트 얼마야?"라고 물어서(`/api/show`) 그 값으로 판단해요. 이건 **모델이 학습된 한계치**라, 사용자가 마음대로 못 올립니다.
2. **그래서 `num_ctx`로는 64K 관문을 통과시킬 수 없습니다.** `num_ctx`는 "이번에 메모리를 얼마나 쓸까"라는 **런타임 설정**일 뿐이고, 모델의 타고난 한계(예: qwen3는 40,960)를 넘기면 오히려 **그 한계로 깎입니다.** 그래서 작은 모델에 `num_ctx 64000`을 줘도 화면엔 `40,960`으로 뜨고 거부당해요.

결론은 단순합니다. **타고난 컨텍스트가 64K 이상인 모델을 골라야 합니다.** 우리가 2단계에서 `llama3.2`(128K)를 받은 이유가 이것입니다.

그러면 `num_ctx`는 왜 설정하냐고요? 헤르메스가 "이 모델 128K나 되네"라고 믿고 긴 컨텍스트로 요청을 보내는데, **Ollama의 런타임 기본 컨텍스트는 그보다 훨씬 작아서**(보통 수천 토큰) 그냥 두면 대화가 잘립니다. 그래서 **런타임 창을 64K로 맞춰** 둡니다. `llama3.2`는 128K가 한계라 `64000`은 안 깎이고 그대로 적용됩니다.

`Modelfile`은 딱 두 줄짜리 텍스트 파일입니다. `echo`로 한 줄씩 만듭니다.

```
echo 'FROM llama3.2:3b' > llama3.2-3b-64k.Modelfile
echo 'PARAMETER num_ctx 64000' >> llama3.2-3b-64k.Modelfile
```

> 💡 **왜 `echo` 두 줄로 만드나요?** 인터넷에 흔한 `cat > 파일 <<'EOF' ... EOF` (heredoc) 방식은 **터미널에 붙여넣을 때 자주 깨집니다.** `cat`이 입력 대기 상태로 멈추고(`[1]+ Stopped`), 뒤이은 `FROM`·`PARAMETER` 줄이 따로 실행돼 `command not found`가 나면서 빈 파일이 만들어져요. `echo` 두 줄은 각각 독립 명령이라 붙여넣기에서 안 깨집니다. (에디터에 익숙하면 `nano llama3.2-3b-64k.Modelfile`로 직접 두 줄을 적어도 됩니다.)

내용이 제대로 들어갔는지 확인하고, 모델을 굽습니다.

```
cat llama3.2-3b-64k.Modelfile     # FROM / PARAMETER 두 줄이 보이면 OK
ollama create llama3.2-3b-64k -f llama3.2-3b-64k.Modelfile
```

> ⚠️ `Error: no FROM line`이 나면 Modelfile이 **비어 있다는 뜻**입니다. 위 `cat`으로 두 줄이 보이는지 먼저 확인하세요(heredoc으로 만들다 깨진 경우가 대부분). 빈 파일이면 `echo` 두 줄을 다시 실행해 만들면 됩니다.

## 2. 헤르메스용 64K 컨텍스트 모델 만들기 (Windows)

개념은 Mac/WSL과 완전히 같습니다. 헤르메스는 모델의 "타고난(native) 컨텍스트"를 먼저 확인하기 때문에, 한계치가 큰 `llama3.2(128K)`를 기반으로 삼고, Ollama의 런타임 메모리 설정(`num_ctx`)을 64,000으로 맞춰주는 Modelfile을 만들어야 합니다.

다만, Windows의 기본 터미널(명령 프롬프트 또는 PowerShell)에서는 `echo` 명령어와 파일 출력 방향 지정(`>` 및 `>>`)의 동작 방식이 Mac/Linux와 조금 다릅니다. 인코딩 문제나 예기치 않은 공백이 들어가는 것을 막기 위해 **Windows 환경에 최적화된 방법**으로 진행합니다.

사용 중인 터미널(명령 프롬프트 또는 PowerShell)에 맞춰 아래 명령어를 복사해 붙여넣으세요.

### 💡 방법 A: PowerShell 기준 (추천)

윈도우에서 가장 많이 쓰이는 PowerShell 창을 열고 아래 명령어를 한 줄씩 실행합니다. 마찬가지로 터미널에서 깨지지 않도록 독립된 명령어로 구성했습니다.

PowerShell

```
Set-Content -Path .\llama3.2-3b-64k.Modelfile -Value 'FROM llama3.2:3b'
Add-Content -Path .\llama3.2-3b-64k.Modelfile -Value 'PARAMETER num_ctx 64000'
```

> **왜 `echo` 대신 `Set-Content`를 쓰나요?** Windows PowerShell에서 `echo '문자열' > 파일`을 쓰면 파일이 UTF-16 인코딩으로 저장되어, 추후 Ollama가 파일 내용을 읽지 못하고 오류를 내뿜는 경우가 있습니다. `Set-Content`를 사용하면 가장 안전한 인코딩으로 깔끔하게 두 줄짜리 Modelfile이 만들어집니다.

### 💡 방법 B: 명령 프롬프트 (cmd) 기준

만약 익숙한 검은색 cmd 창을 사용 중이시라면 아래와 같이 입력합니다. (단, cmd의 `echo`는 따옴표까지 파일에 그대로 적어버리므로 따옴표를 제외하고 입력해야 합니다.)

DOS

```
echo FROM llama3.2:3b > llama3.2-3b-64k.Modelfile
echo PARAMETER num_ctx 64000 >> llama3.2-3b-64k.Modelfile
```

### 모델 굽기 (공통)

내용이 제대로 들어갔는지 Windows용 출력 명령어(`type`)로 확인한 뒤, Ollama 모델을 생성합니다. (PowerShell과 cmd 모두 동일합니다.)

DOS

```
type llama3.2-3b-64k.Modelfile     # FROM / PARAMETER 두 줄이 보이면 OK
ollama create llama3.2-3b-64k -f llama3.2-3b-64k.Modelfile
```

⚠️ **Error: no FROM line 또는 인코딩 에러가 난다면?** Modelfile이 비어 있거나 윈도우 특유의 줄바꿈/인코딩 문제일 확률이 높습니다. 이럴 때는 복잡하게 명령어를 쓰는 대신, 바탕화면에 메모장(Notepad)을 켜서 아래 두 줄을 타이핑한 뒤, 파일명을 `llama3.2-3b-64k.Modelfile`로 저장(형식은 모든 파일)해서 해당 디렉토리에 넣어주는 것이 가장 확실하고 속 편한 방법입니다.

Plaintext

```
FROM llama3.2:3b
PARAMETER num_ctx 64000
```
