본 문서는 Hermes Agent와 로컬 Ollama 환경을 안정적으로 연동하고, 컨텍스트 잘림 현상을 해결하기 위해 설정했던 히스토리를 정리한 연동 가이드입니다.

---

## 1. 개요 및 문제 현상

- **목표**: Hermes Agent의 메인 추론 모델로 로컬 Ollama의 `gemma4:e4b` 모델을 연동합니다.
- **최초 상태**: [config.yaml](file:///c:/Users/ojpfi/AppData/Local/hermes/config.yaml)에 단순하게 Ollama 주소와 모델명(`gemma4:e4b`)을 입력하였으나, 질문 입력 시 답변이 한두 단어 출력 후 완전히 멈추는 현상이 발생했습니다.
- **원인**: Ollama 모델 구동 시 설정되는 기본 컨텍스트 길이(2,048 ~ 4,096 토큰) 제한으로 인해, 대용량 프롬프트(약 17k 토큰)를 전송하는 Hermes Agent의 특성상 컨텍스트가 초과되어 발생한 문제였습니다.

---

## 2. 해결 과정

### [1단계] 컨텍스트 64k 지정 커스텀 모델 생성

Ollama 자체에서 모델을 항상 충분한 컨텍스트 크기로 올릴 수 있도록 설정 파라미터가 수정된 새로운 커스텀 모델을 생성했습니다.

1. **Modelfile 작성** ([Modelfile](file:///C:/Users/ojpfi/.gemini/antigravity-ide/scratch/Modelfile))
   ```dockerfile
   FROM gemma4:e4b
   PARAMETER num_ctx 64000
   ```
2. **Ollama 모델 빌드**
   터미널에서 아래 명령을 실행하여 `gemma4:e4b-64k`라는 이름의 커스텀 모델을 새롭게 등록했습니다.
   ```bash
   ollama create gemma4:e4b-64k -f Modelfile
   ```

### [2단계] Hermes 설정 변경 ([config.yaml](file:///c:/Users/ojpfi/AppData/Local/hermes/config.yaml))

Hermes Agent가 해당 64k 모델을 인지하고 자체 한계값을 64k 이상으로 지정하도록 설정을 변경했습니다.

- **설정 파일 위치**: [config.yaml](file:///c:/Users/ojpfi/AppData/Local/hermes/config.yaml)

```yaml
model:
  api_key: ollama
  base_url: http://127.0.0.1:11434/v1
  context_length: 65536 # Hermes Agent가 인식할 최대 컨텍스트
  default: gemma4:e4b-64k # 새로 생성한 64k 커스텀 모델 지정
  ollama_num_ctx: 64000 # Ollama에 전송할 컨텍스트 기본 한도
  provider: ollama-launch

providers:
  ollama-launch:
    api: http://127.0.0.1:11434/v1
    default_model: gemma4:e4b-64k
    models:
      - gemma4:e4b-64k
    name: Ollama
```
