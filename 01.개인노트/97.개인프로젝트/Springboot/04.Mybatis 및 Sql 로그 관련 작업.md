# MyBatis 설정 및 SQL 로그 적용 가이드

본 문서는 `springboot_boilerplate` 프로젝트의 **MyBatis 프레임워크 연동, Java 기반 명시적 설정, P6Spy SQL 로깅 적용 및 트러블슈팅 절차**를 순서대로 정리한 가이드입니다.

---

## Step 1. 빌드 의존성 추가 (`build.gradle`)

MyBatis 프레임워크, MariaDB JDBC 드라이버, 그리고 실행 SQL 파라미터 로깅을 위한 P6Spy 라이브러리를 `build.gradle`에 추가합니다.

```groovy
dependencies {
    // MyBatis Spring Boot Starter & Core
    implementation 'org.mybatis.spring.boot:mybatis-spring-boot-starter:3.0.4'
    implementation 'org.mybatis:mybatis:3.5.16'
    implementation 'org.mybatis:mybatis-spring:3.0.4'

    // MariaDB JDBC Driver
    runtimeOnly 'org.mariadb.jdbc:mariadb-java-client:3.5.3'

    // P6Spy SQL 쿼리 로깅 (개발/디버깅 환경 전용)
    developmentOnly 'com.github.gavlyukovskiy:p6spy-spring-boot-starter:1.11.0'
}
```

## Step 2. Java 기반 MyBatis 핵심 설정 (`MyBatisConfig.java`)

Spring Boot Executable WAR 패키징 및 Docker 배포 환경에서 프로퍼티 설정만 사용할 경우 발생하는 매퍼 XML 인식 유실 문제를 방지하기 위해, Java Config 클래스로 `SqlSessionFactory`와 `SqlSessionTemplate`을 직접 빈(Bean)으로 등록합니다.

- **파일 위치**: `D:/springboot_boilerplate/src/main/java/com/api/config/MyBatisConfig.java`

```java
package com.api.config;

import org.apache.ibatis.session.SqlSessionFactory;
import org.mybatis.spring.SqlSessionFactoryBean;
import org.mybatis.spring.SqlSessionTemplate;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.io.support.PathMatchingResourcePatternResolver;

import javax.sql.DataSource;

/**
 * MyBatis 설정 클래스
 * WAR 패키징 및 Docker 배포 환경에서 매퍼 XML 스캔 오류를 방지하기 위해 SqlSessionFactory를 직접 구성합니다.
 */
@Configuration
public class MyBatisConfig {

    @Bean
    public SqlSessionFactory sqlSessionFactory(DataSource dataSource) throws Exception {
        SqlSessionFactoryBean sessionFactoryBean = new SqlSessionFactoryBean();
        sessionFactoryBean.setDataSource(dataSource);

        // DTO 패키지 TypeAlias 설정
        sessionFactoryBean.setTypeAliasesPackage("com.api.common.dto,com.api.sample.dto");

        // 매퍼 XML 위치 설정 (WAR / JAR 환경 지원을 위해 classpath*: 사용)
        PathMatchingResourcePatternResolver resolver = new PathMatchingResourcePatternResolver();
        sessionFactoryBean.setMapperLocations(resolver.getResources("classpath*:mapper/**/*.xml"));

        return sessionFactoryBean.getObject();
    }

    @Bean
    public SqlSessionTemplate sqlSessionTemplate(SqlSessionFactory sqlSessionFactory) {
        return new SqlSessionTemplate(sqlSessionFactory);
    }
}
```

## Step 3. 공통 DAO 및 매퍼 연동 구성

1. **인터페이스 정의 (`IDao.java`)**: CRUD 기본 인터페이스 메서드 제공
2. **공통 DAO 구현 (`CommonDao.java`)**: `SqlSession`을 주입받아 모든 XML 매퍼 쿼리를 `namespace.id` 문자열 기반으로 동적 실행
   - 파일 위치: `D:/springboot_boilerplate/src/main/java/com/api/common/dao/CommonDao.java`

3. **도메인 DAO (`RedmineDao.java`)**: 별도의 매퍼 인터페이스 파일 없이 `CommonDao`를 통해 XML 네임스페이스 쿼리를 직접 호출

## Step 4. 실행 SQL 콘솔 로그 설정 (P6Spy)

### 4-1. 1차 — MyBatis 내장 로거 (`StdOutImpl`) (참고)

```properties
mybatis.configuration.log-impl=org.apache.ibatis.logging.stdout.StdOutImpl
```

- 파라미터가 `?` 위치지정자로 표시되며, 파라미터 값과 SQL이 별도의 줄로 출력되는 한계 존재.

### 4-2. 2차 — 파라미터가 치환된 완성형 SQL 표시 (P6Spy 적용)

파라미터 값이 실제 값으로 치환된 완벽한 실행 SQL을 콘솔에 출력하기 위해 P6Spy 설정을 적용합니다.

#### 프로파일별 로깅 설정

- **공통 프로필 (`application.properties`)**:
  ```properties
  decorator.datasource.p6spy.enable-logging=false
  decorator.datasource.p6spy.logging=slf4j
  ```
- **개발 환경 (`application-dev.properties`)**:
  ```properties
  decorator.datasource.p6spy.enable-logging=true
  ```
- **운영 환경 (`application-prod.properties`)**:
  ```properties
  decorator.datasource.p6spy.enable-logging=false
  ```

#### 콘솔 출력 결과 예시

```text
SELECT * FROM users WHERE id = ?
SELECT * FROM users WHERE id = 1;
```

## Step 5. 트러블슈팅 및 해결 이력

### 5-1. `NoClassDefFoundError: SqlSession` (SmartTomcat / IDE 캐시)

- **증상**: SmartTomcat 실행 시 `CommonDao` 생성 과정에서 `SqlSession` 클래스를 찾지 못해 구동 실패.
- **원인**: IDE의 아티팩트(`WEB-INF/lib`)가 Gradle 최신 의존성 반영 이전 상태로 캐싱됨.
- **조치**: Gradle Reload 및 Project Rebuild 진행 후 재배포.

### 5-2. `Mapped Statements collection does not contain value for ...` (Docker / WAR 배포 시)

- **증상**: Docker 컨테이너 배포 후 API 호출 시 `java.lang.IllegalArgumentException: Mapped Statements collection does not contain value for statement_id` 발생.
- **원인**: Executable WAR 구조(`WEB-INF/classes/mapper/`)에서 `classpath:` 접두사를 사용하는 스프링 부트 자동 설정만으로는 클래스로더가 매퍼 XML 파일을 인덱싱하지 못함.
- **조치**: `MyBatisConfig.java`를 추가하여 `PathMatchingResourcePatternResolver`로 `classpath*:mapper/**/*.xml` 매퍼 리소스를 명시적으로 바인딩 및 빈 등록 완료.

## Step 6. 검증 및 테스트 방법

1. **테스트 쿼리 호출**: `GET http://localhost:8081/redmine/users/1`
2. **콘솔 로그 확인**: 파라미터가 정상 치환된 SQL 실행 로그 확인
3. **Docker 배포 검증**:

   ```bash
    docker build --no-cache -t springboot-api:latest .
    docker run -d -p 8080:8080 --link mariadb:mariadb --name springboot-api springboot-api:latest
   ```
