# MyBatis 설정 및 SQL 로그 작업 정리

## 1. MyBatis 연동 설정

### 1-1. 의존성 추가 (`build.gradle`)

```groovy
implementation 'org.mybatis.spring.boot:mybatis-spring-boot-starter:3.0.4'
implementation 'org.mybatis:mybatis:3.5.16'
implementation 'org.mybatis:mybatis-spring:3.0.4'
runtimeOnly 'org.mariadb.jdbc:mariadb-java-client:3.5.3'
```

### 1-2. 매퍼/타입 경로 설정 (`application.properties`)

```properties
mybatis.mapper-locations=classpath:mapper/**/*.xml
mybatis.type-aliases-package=com.api.common.dto,com.api.sample.dto
```

### 1-3. 공통 DAO 구성

- `IDao` : select/selectList/insert/update/delete 표준 인터페이스
- `CommonDao` : `SqlSession`을 주입받아 `IDao`를 구현, 모든 매퍼 statement를 `namespace.id` 문자열로 실행
- 각 도메인 DAO(`RedmineDao` 등)는 `CommonDao`를 통해 통계/매퍼 인터페이스 없이 XML 네임스페이스로 직접 SQL 호출

### 1-4. 트러블슈팅 — `NoClassDefFoundError: SqlSession`

- 증상: SmartTomcat(IntelliJ) 배포 시 `CommonDao` bean 생성 중 `org.apache.ibatis.session.SqlSession` 클래스를 찾지 못함
- 원인: Gradle에는 mybatis 의존성이 정상 반영되어 있으나, IntelliJ/SmartTomcat이 사용하는 exploded 아티팩트(`WEB-INF/lib`)가 최신 `build.gradle` 변경 이전 상태로 캐시되어 있었음
- 조치: IDE에서 Gradle Reload → Rebuild Project → Project Structure의 Artifact에 mybatis 관련 jar 포함 여부 확인 후 재배포 (코드 변경 없음)

## 2. 실행 SQL 콘솔 로그 설정

### 2-1. 1차 — MyBatis 내장 로거 (`StdOutImpl`)

```properties
mybatis.configuration.log-impl=org.apache.ibatis.logging.stdout.StdOutImpl
```

- 매퍼가 인터페이스 없이 XML 네임스페이스(`sample`)로만 구성되어 있어, 패키지 기반 `logging.level.*=DEBUG` 방식 대신 MyBatis 로그 구현체를 직접 지정하는 방식 사용
- 출력 형태: `Preparing: SELECT * FROM users WHERE id = ?` + `Parameters: 1(Integer)` (SQL과 파라미터 값이 별도 줄로 표시, SQL 문자열 자체에는 `?` placeholder 유지)

### 2-2. 2차 — 파라미터 값이 치환된 완성 SQL 표시 (p6spy)

MyBatis 자체 로거는 SQL 문자열에 실제 값을 치환해서 보여주는 기능이 없어, JDBC 레벨에서 실행 SQL을 가로채는 p6spy로 교체.

**의존성 추가 (`build.gradle`)**

```groovy
developmentOnly 'com.github.gavlyukovskiy:p6spy-spring-boot-starter:1.11.0' // 개발/디버깅 환경 전용
```

**설정 (프로필별 분리)**

- `application.properties` (공통 기본값 비활성화): `decorator.datasource.p6spy.enable-logging=false`
- `application-dev.properties` (개발 환경 활성화): `decorator.datasource.p6spy.enable-logging=true`
- `application-prod.properties` (운영 환경 비활성화): `decorator.datasource.p6spy.enable-logging=false`

**동작 방식**: `spring-boot-data-source-decorator`가 애플리케이션의 `DataSource`를 자동으로 p6spy 프록시로 감싸므로, `spring.datasource.url`/`driver-class-name`은 그대로 두면 됨 (수동으로 `jdbc:p6spy:...` URL로 바꿀 필요 없음).

**출력 형태 (검증 완료)**

```
SELECT * FROM users WHERE id = ?
SELECT * FROM users WHERE id = 1;
```

원본 SQL과, 파라미터 값이 치환된 실행 SQL이 함께 콘솔에 출력됨.

**전체 옵션 (`decorator.datasource.p6spy.*`, spring-boot-data-source-decorator 제공)**

| 속성                                               | 기본값    | 설명                                                                                                                |
| -------------------------------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------- |
| `decorator.datasource.p6spy.enable-logging`        | `true`    | JDBC 이벤트 로깅 on/off — **현재 적용: `true`**                                                                     |
| `decorator.datasource.p6spy.multiline`             | `true`    | 한 줄(`SingleLineFormat`) 대신 여러 줄(`MultiLineFormat`)로 출력                                                    |
| `decorator.datasource.p6spy.logging`               | `slf4j`   | 출력 대상: `slf4j` \| `sysout` \| `file` \| `custom` — **현재 적용: `slf4j`** (프로젝트 기존 로깅 설정을 그대로 탐) |
| `decorator.datasource.p6spy.log-file`              | `spy.log` | `logging=file`일 때 로그 파일 경로                                                                                  |
| `decorator.datasource.p6spy.custom-appender-class` | -         | `logging=custom`일 때 사용할 `FormattedLogger` 구현 클래스                                                          |
| `decorator.datasource.p6spy.log-format`            | -         | 지정하면 `CustomLineFormat` 사용 (커스텀 포맷 문자열)                                                               |
| `decorator.datasource.p6spy.log-filter.pattern`    | -         | 정규식과 매칭되는 로그만 출력                                                                                       |
| `decorator.datasource.p6spy.exclude-categories`    | `[]`      | 특정 카테고리 로그 제외. 값: `error, info, debug, statement, batch, commit, rollback, outage, result, resultset`    |

`enable-logging`, `logging` 두 항목만 명시적으로 설정했고 나머지는 기본값 그대로 사용 중.

**`log-format` 커스텀 포맷 토큰**

```
%(currentTime) %(executionTime) %(category) %(connectionId) %(sql) %(sqlSingleLine) %(effectiveSql) %(effectiveSqlSingleLine)
```

- `%(sql)` — 원본 SQL (`?` 유지)
- `%(effectiveSql)` — 값이 치환된 SQL (지금 출력 결과가 이 방식)
- 기본 포맷: `%(currentTime)|%(executionTime)|%(category)|connection%(connectionId)|%(sqlSingleLine)`

**decorator가 노출하지 않는, raw `spy.properties`로만 되는 옵션**

classpath 루트에 `spy.properties` 파일을 직접 추가해야 적용됨 (미적용):

| 속성                                          | 설명                                                                          |
| --------------------------------------------- | ----------------------------------------------------------------------------- |
| `executionThreshold`                          | 지정 시간(ms)보다 오래 걸린 쿼리만 로깅 (slow query 필터)                     |
| `outagedetection` / `outagedetectioninterval` | 지정 시간(초) 넘게 실행 중인 statement를 반복 로깅 (DB 응답 지연/장애 감지용) |
| `stacktrace` / `stacktraceclass`              | 각 로그에 호출 스택트레이스 출력                                              |
| `dateformat`                                  | 타임스탬프를 사람이 읽을 수 있는 형식으로 변경                                |
| `driverlist`                                  | JNDI 등 자동 드라이버 등록이 안 되는 환경에서 드라이버 수동 등록              |

## 3. 검증 방법 (참고)

1. 파라미터가 있는 임시 매퍼 statement(`WHERE id = #{id}`)와 DAO/Service/Controller 메서드를 추가
2. `./gradlew compileJava processResources` 로 devtools 재시작 유도 (bootRun 실행 중 소스만 수정하면 자동 재컴파일이 되지 않으므로 수동 트리거 필요)
3. `curl http://localhost:8081/redmine/users/{id}` 호출 후 콘솔 로그에서 치환된 SQL 확인
4. 검증용 임시 코드는 확인 후 모두 원복

## 4. 향후 필요 시 확장 (미적용)

- 로그가 과도하게 많아질 경우: `decorator.datasource.p6spy.exclude-categories=commit,rollback` 로 커밋/롤백 로그 제외
- 느린 쿼리만 보고 싶은 경우: `spy.properties`에 `executionThreshold` 설정
- 그 외 옵션 전체 목록은 2-2 항목 참고
